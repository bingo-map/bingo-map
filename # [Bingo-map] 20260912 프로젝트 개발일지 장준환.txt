**1. 전반적인 구현 수준 요약**

* **구현 완성도**: 데이터베이스 연동과 화면 출력에 필요한 핵심 기반 구조는 약 **85%** 완성된 상태입니다.
* **현재 상태**: 오라클 데이터베이스에 저장된 맛집 정보를 자바 프로그램이 읽어와 HTML 화면으로 띄워주는 전체 흐름이 연결되어 있습니다. 다만 상세 페이지에서 보여줄 **식당별 개별 메뉴 목록**은 아직 데이터베이스 테이블이 따로 쪼개져 있지 않아 연결 작업이 더 필요합니다.

---

**2. 단계별 구현 현황 및 용어 해설**

**데이터베이스 및 데이터 설계 계층**

* **Oracle 11g 연동 설정 완료**: 설정 파일(`application.yml`)에 오라클 DB 접속 정보와 **JDBC 드라이버**(자바 프로그램과 데이터베이스를 이어주는 전용 연결 통로), **HikariCP**(데이터베이스 접속 연결선을 미리 만들어두고 빠르게 재사용하는 커넥션 풀 관리 도구), **JPA/Hibernate**(SQL 쿼리문을 일일이 손으로 짜지 않아도 자바 코드로 데이터를 쉽게 다룰 수 있게 해주는 도구) 환경이 구성되어 실제 데이터베이스와 정상 연결되었습니다.
* **`Restaurant` Entity(엔티티)**: 자바 객체와 실제 데이터베이스 테이블의 컬럼(열)을 1:1로 짝지어둔 핵심 데이터 설계도입니다. 매장 번호(`id`), 가게 이름(`name`), 음식 종류(`category`), 소개글(`description`), 사진 경로(`imageUrl`), 주소(`address`)가 오라클 테이블과 연결되어 있습니다.
* **`RestaurantRepository`(레포지토리)**: 데이터베이스에 실제로 SELECT(조회) 명령을 날려주는 창구입니다. 기본 제공 기능을 상속받아 전체 목록 가져오기(`findAll()`)와 가게 1개 상세 조회(`findById()`) 쿼리가 자동으로 작동합니다.

**데이터 가공 및 전달 계층**

* **`RestaurantDto`(DTO, 데이터 전송 객체)**: 데이터베이스 테이블 원본(엔티티)을 화면에 그대로 노출하지 않고, 화면 출력에 딱 필요한 데이터만 안전하게 담아서 나르는 배달용 상자 역할을 합니다.
* **`RestaurantService`(서비스)**: 실제 비즈니스 로직(업무 처리 흐름)을 담당하는 공간입니다.
* `getAllRestaurants()`: DB에서 등록된 맛집 목록을 전부 꺼내와 DTO 상자에 담아 리스트로 정리합니다.
* `getRestaurantById(Long id)`: 사용자가 클릭한 특정 맛집 번호(ID)를 받아 해당 식당 데이터 1건을 조회합니다.



**화면 제어 및 템플릿 계층**

* **`RestaurantController`(컨트롤러)**: 사용자의 웹 브라우저 요청(URL 주소)을 받아서 알맞은 화면을 띄워주는 안내 데스크입니다.
* `GET /restaurants`: 브라우저가 맛집 목록을 요청하면 DB에서 목록을 가져와 화면으로 넘겨줍니다.
* `GET /restaurants/detail?id=1`: 특정 가게 번호를 넘겨받아 DB에서 1건을 찾아 상세 화면으로 보내줍니다.


* **Thymeleaf(타임리프) 템플릿 연동**: 서버(자바)에서 보낸 DB 데이터를 HTML 화면 태그 안에 꽂아 넣어 동적으로 페이지를 만들어주는 화면 제작 도구입니다.
* `restaurants.html`: 서버에서 넘어온 맛집 목록 개수만큼 반복문(`th:each`)을 돌려 화면에 카드 형태로 뿌려줍니다.
* `detail.html`: 클릭한 식당의 이름, 사진, 주소를 화면 텍스트(`th:text`)에 정확하게 꽂아줍니다.
